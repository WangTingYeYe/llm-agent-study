# 简单的PDF RAG应用程序

这是一个使用阿里百炼（DashScope）和LangChain框架构建的智能PDF问答系统。通过先进的RAG（检索增强生成）技术，实现对PDF文档的智能理解和问答。

## ✨ 功能特性

### 🚀 核心功能
- ✅ **官方SDK集成** - 使用LangChain官方的`ChatTongyi`和`DashScopeEmbeddings`
- ✅ **智能PDF处理** - 支持PDF文档自动加载、解析和向量化
- ✅ **向量检索** - 基于Chroma向量数据库的高效相似度检索
- ✅ **智能问答** - 基于文档内容的精准问答系统

### 🌟 Web界面特性
- 🎨 **现代化UI** - 基于Streamlit的美观Web界面
- 📁 **拖拽上传** - 支持PDF文件拖拽上传（最大200MB）
- 🔑 **在线配置** - 界面内直接设置DashScope API密钥
- 📊 **实时进度** - 文档处理过程可视化显示
- 💬 **聊天历史** - 完整的问答历史记录

### 🚀 智能预处理系统
- 🧹 **文本清理** - 自动移除噪音字符、标准化Unicode
- 📄 **页眉页脚移除** - 智能识别并移除页码、页眉页脚
- 🔗 **连字符处理** - 修复跨行连字符分割问题
- 📝 **结构增强** - 自动识别标题，优化文档结构
- 📈 **压缩统计** - 显示预处理后的内容优化比例

### ⚙️ 高级配置
- 🎛️ **模型选择** - 支持多种Embedding和LLM模型
- ✂️ **分割参数** - 可调整文本分割块大小和重叠
- 🔍 **检索配置** - 自定义检索文档数量
- 📝 **预处理开关** - 可选择启用/禁用智能预处理

### 🛡️ 系统优化
- 🔇 **日志优化** - 抑制第三方库噪音日志
- 🚫 **遥测禁用** - 完全禁用PostHog等遥测服务
- ⚡ **性能优化** - 高效的向量存储和检索
- 🛠️ **错误处理** - 完善的异常处理机制

## 📋 环境要求

- **Python**: 3.8+
- **API密钥**: 阿里百炼DashScope API密钥
- **内存**: 建议4GB以上（处理大型PDF时）

## 🏗️ 技术架构

### 核心组件
- **PDFPreprocessor**: 智能PDF预处理器
- **StreamlitRAGApp**: RAG应用核心类
- **ChatTongyi**: 阿里百炼LLM集成
- **DashScopeEmbeddings**: 阿里百炼Embedding集成
- **Chroma**: 向量数据库

### 工作流程
1. **文档上传** → PDF文件上传到应用
2. **智能预处理** → 文本清理、去噪、结构优化
3. **文档分割** → 递归字符分割器处理
4. **向量化** → 使用text-embedding-v2模型
5. **存储** → Chroma向量数据库存储
6. **检索** → 相似度检索相关文档块
7. **生成** → qwen-turbo模型生成回答

## ⚙️ 配置参数

### 模型配置
```python
# Embedding模型
embedding_models = [
    "text-embedding-v1",
    "text-embedding-v2",  # 推荐
    "text-embedding-v3"
]

# LLM模型
llm_models = [
    "qwen-turbo",         # 推荐，速度快
    "qwen-plus",          # 平衡性能
    "qwen-max",           # 最强性能
    "qwen-max-longcontext"  # 长文本
]
```

### 处理参数
- **chunk_size**: 文本分割块大小（500-2000，默认1000）
- **chunk_overlap**: 文本块重叠大小（0-200，默认100）
- **k_docs**: 检索文档数量（1-10，默认3）
- **enable_preprocessing**: 是否启用智能预处理（默认True）

## 🔧 故障排除

### 常见问题

**Q: API调用失败**
```
解决方案:
1. 检查API密钥是否正确
2. 确认网络连接正常
3. 验证API额度充足
4. 检查模型名称是否正确
```

**Q: PDF处理失败**
```
解决方案:
1. 检查PDF文件是否损坏
2. 确认文件大小不超过200MB
3. 尝试禁用预处理功能
4. 检查PDF是否为扫描版（需OCR）
```

**Q: 回答不准确**
```
优化建议:
1. 调整检索文档数量(k_docs)
2. 优化文本分割参数
3. 使用更强的LLM模型
4. 启用智能预处理功能
```

**Q: 内存不足**
```
解决方案:
1. 减小chunk_size参数
2. 分批处理大型文档
3. 增加系统内存
4. 使用更轻量的模型
```

## 📈 性能指标

- **文档大小**: 支持最大200MB PDF
